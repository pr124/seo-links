## Rules for existing and future posts

- **Scope:** Apply to all existing resources and all future user-supplied posts.
- **Relevance:** Include usable SEO research, technical work, content improvement, measurement, or a destination with a plausible product-discovery, editorial, publishing or submission role. A high DR claim alone is not relevance.
- **Deduplication:** Compare the whole repository, including tools, research sources, MCP integrations and destination identities. Normalize www, redirects, alternate names and homepage/submission routes. Keep independent GitHub repositories separate. Store additional source references against an existing destination rather than creating another guide listing.
- **Articles:** Use a descriptive title, original article/post link and a short takeaway. Do not copy the full article. Establish the topic before adding it to the guide.
- **Updates:** Update an existing entry only with useful new facts, recovered practical content, checked submission details or source provenance.
- **Evidence:** Separate official guidance, historical trial evidence, patent descriptions, author interpretation and unverified outcomes. A patent or leaked field name does not establish a deployed ranking rule.
- **Withholding:** Keep inaccessible implementation details, pure promotion, repeated basic advice, ambiguous destinations, unsupported guarantees and poor-fit platforms in the source register rather than the main guide.
- **Source preservation:** Retain original post URLs, authors, dates, list positions, supplied-text coverage and remaining access gaps. Partial threads must remain labelled partial.
